THIRD-PARTY NOTICES FOR KODEOS
===============================

This file lists the third-party software compiled into the kodeOS firmware
image (kodeos.bin) that ships in the factory pack for the Kode Dot
(ESP32-P4). The factory pack is five files - bootloader.bin,
partition-table.bin, ota_data_initial.bin, kodeos.bin and storage.bin -
flashed at fixed offsets by flash.sh / esptool. storage.bin, the internal FAT,
also carries the ESP32-C5 radio-coprocessor firmware (c5_slave.bin, built
from kodediy/kode_slave_c5: Espressif's esp-hosted-mcu slave, Apache-2.0, on
ESP-IDF v6.0.2). Its own third-party components are not listed in this
notice.

kodeOS is built with ESP-IDF v6.1.0 (Apache-2.0, Espressif Systems) for the
ESP32-P4 target. What follows covers every third-party component whose
object code is present in the linked kodeos.elf, plus three components
stated plainly whatever their licensing status (QP/C, RFAL, and the
Proxmark3 key dictionary). A
"not in this firmware" section at the end lists components that are present
in the source tree or the dependency lock file but were confirmed NOT to
contribute any linked object code to this image.

Where a source header gives a copyright line, it is reproduced exactly as
written. Where none could be found, this file says "copyright: see
upstream" rather than inventing one.

COMPONENTS CONFIRMED NOT COMPILED INTO THIS IMAGE
================================================================================
The following are present in the source tree, in dependencies.lock,
and/or in managed_components/, but were confirmed - either by Kconfig or
by inspecting the final link map (build/kodeos.map) for linked object
files from their archives - to contribute NO object code to this
release's kodeos.elf. They are listed here for completeness, not because
they need a notice in this firmware.

  - cmake_utilities 0.5.3, eppp_link 1.1.6, wifi_remote_over_eppp 0.3.3,
    esp_serial_slave_link 1.1.2 (all Espressif; Apache-2.0, except
    wifi_remote_over_eppp which is Unlicense OR CC0-1.0). These are
    transitive dependencies of esp_wifi_remote's alternative "EPPP"
    transport backend. kodeOS talks to the ESP32-C5 over esp_hosted's
    SDIO transport instead, so this backend is never selected. Zero
    object files from any of their archives appear in build/kodeos.map.

  - protobuf-c, as vendored directly under ESP-IDF's own protobuf-c
    component (distinct from the copy esp_hosted bundles - see #11
    above, which IS linked). Zero objects from ESP-IDF's own
    libprotobuf-c.a are linked; esp_hosted uses its own bundled copy.

  - wpa_supplicant (ESP-IDF component). Zero objects linked. WiFi/WPA
    negotiation happens on the ESP32-C5 radio coprocessor's own
    firmware, not in this P4 image.

  - esp_hid, protocomm, esp_local_ctrl, esp_https_server, spiffs (all
    ESP-IDF components). All appear in the build's component graph
    (each gets compiled to its own static library because something in
    the Kconfig/dependency chain configures it), but zero object files
    from any of them are pulled into the final linked kodeos.elf.

  - Xtensa-only ROM notices from ESP-IDF's own COPYRIGHT.rst (Tensilica
    libhal, TinyBasic Plus, TJpgDec mask-ROM code, the Zephyr-derived
    USB device stack). These apply only to Xtensa-based ESP chips; the
    Kode Dot's ESP32-P4 is dual RISC-V, so none of it is in this image.
